# 数据备份系统架构视图

本目录是系统架构设计的唯一入口。结构化模型位于 `model.yaml`，生成的 PlantUML 源文件、SVG、PNG 和说明文档不得手工修改；统一运行 `uv run scripts/update_system_design.py` 更新。

## 维护范围

| 层级或视图 | 当前内容 | 维护策略 |
|---|---|---|
| C1 System Context | 用户、调度器、源文件系统、本地及 WebDAV/S3 存储 | 持续维护 |
| C2 Container | GUI、CLI、守护进程、本地接口、备份核心和 SQLite | 持续维护 |
| C3 Component | 仅展开关键的备份核心容器 | 持续维护 |
| C4 Code | 不建立手工图 | 由未来代码和 API 表达 |
| Deployment | macOS 工作站、本地卷和 HTTPS 远程存储 | 持续维护 |
| Sequence | 配置任务、执行备份、浏览与恢复 | 随行为变化维护 |
| Logical class | 领域模型及服务接口 | 作为课程设计和实现前逻辑约束保留 |

完整图表和逐图说明见[系统设计文档](system-design.md)。当前项目尚未处于包含多个同级软件系统的企业环境，因此不建立 System Landscape；状态机、ER、流程图和数据流图将在出现需要单独解释的复杂状态、持久化模型或算法后按需增加。

## 一致性边界

- C1 用自然语言行为规格和顺序图描述用户可观察结果。
- C2 明确可运行单元、技术方向和通信边界，对应集成测试。
- C3 明确核心内部职责、端口及适配器，对应构件测试。
- C4 由代码和单元测试维护，不复制容易漂移的代码结构。
- 所有层级都继承原子快照、认证恢复、错误透明和敏感信息不落日志的约束。
