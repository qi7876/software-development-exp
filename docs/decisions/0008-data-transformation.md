# ADR-0008：加密、打包与压缩管线

- 日期：2026-09-04
- 状态：已接受；参数等待技术探针确定

## 背景

备份仓库需要兼顾大量小文件、增量去重、随机恢复、远程目标请求成本和静态数据保密。直接采用 tar/zip 作为主仓库格式虽然互操作性好，但不适合内容寻址、跨快照复用和小范围随机恢复。加密还会使后续压缩失效，因此数据变换顺序必须固定并写入格式规范。

## 决策

写入管线为：

```text
文件 → 内容定义分块 → 每块独立压缩 → [启用时] 每块独立认证加密 → 块聚合 pack → 目标存储
```

读取与恢复严格按相反顺序进行。压缩和加密的独立单元是内容块，而不是整个 pack，因此恢复单个文件时只需读取相关 pack 范围、认证解密并解压所需块。每个块具有版本化头部，至少记录格式版本、压缩算法、加密算法、非机密参数、密文长度和认证所需信息。

算法选择是仓库格式的可演进能力，不是要求普通用户理解的选项。写入端使用当前安全默认值；读取端根据块头自动选择解密和解压算法。未知必需算法必须明确拒绝读取。

### 加密与密钥

- 每个仓库生成随机 256 位主密钥，内容不直接使用用户口令加密。
- 使用 Argon2id 和独立随机盐从口令派生保护密钥，再用它包裹主密钥。
- 内容采用 XChaCha20-Poly1305 认证加密；每个独立加密单元使用唯一随机 nonce。
- 启用加密时，文件名、目录结构、文件元数据、快照清单和 pack 索引同样经过认证加密。仓库只公开识别格式、解锁所必需的最少信息。
- 启用加密时生成版本化 JSON 文本密钥文件，以 Base64 保存盐、KDF 参数、nonce、密文主密钥和密钥标识；口令和明文主密钥不得写入文件。
- 文本密钥文件可复制到另一台设备；恢复时必须同时提供匹配的密钥文件和正确口令。
- 解密认证通过前只写临时文件；认证失败、密文截断或错误口令时删除临时明文。
- 密钥、口令和可复用认证材料不得出现在日志、崩溃报告或诊断包中。

Argon2id 的具体内存、迭代和并行参数不硬编码在规范中，而是随仓库记录并通过目标 macOS 设备基准确定。参数升级只影响新包裹的主密钥，不要求重加密全部内容。

### 分块与打包

- 大文件使用内容定义分块，以提高文件中间插入内容后的去重率；边界算法和最小/平均/最大块大小由基准测试确定。
- 每个块独立完成压缩以及可选的认证加密后，再把块聚合到不可变 pack，以减少文件系统 inode 和 WebDAV/S3 请求数量。
- pack 尾部或独立加密索引保存键控对象 ID、偏移、密文长度和必要校验信息。
- pack 达到目标大小后封存，封存后不可修改；崩溃遗留的未封存 pack 不进入快照引用。
- 加密清单与 pack 分离，使解锁后浏览快照不必下载全部内容数据。
- tar 可作为导出/互操作格式，但不作为主仓库格式。

普通用户可选择“自动、本地优化、远程存储优化”。这些预设只控制新 pack 的目标大小等布局参数，不改变既有 pack。精确尺寸属于高级诊断信息，由技术探针确定。

### 压缩

- 默认算法为 Zstandard，默认级别通过基准选择并允许用户使用“自动、关闭、快速、平衡、高压缩”预设。
- 每个独立块记录压缩算法；`none` 是合法算法，便于跳过不值得压缩的内容。
- 是否压缩由小样本试压缩或已知不可压缩扩展名辅助判断，但恢复不能依赖文件扩展名。
- 压缩必须发生在加密之前；任何路径都不得尝试压缩密文。

### 用户选项与格式兼容

| 能力 | 普通用户选项 | 格式层行为 |
| --- | --- | --- |
| 加密 | 不加密、口令保护的文本密钥文件 | 新写入固定使用 XChaCha20-Poly1305；密钥文件认证封装主密钥；解密按块头自动识别 |
| 压缩 | 自动、关闭、快速、平衡、高压缩 | MVP 映射到 `none` 或 Zstandard 级别；解压按块头自动识别 |
| 打包 | 自动、本地优化、远程存储优化 | 只改变新 pack 布局，不重写既有数据 |
| 导出 | tar、zip | 仅生成便携副本，不作为备份仓库内部格式 |

普通界面不提供任意密码算法菜单。未来增加新算法时，先增加只读兼容和迁移测试，再允许新仓库写入；已经写入的块始终按自身头部解码。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| AES-256-GCM | 标准且有硬件加速，但 nonce 管理错误代价高；保留为兼容候选，不作为首选 |
| 整仓库或整 pack 单一加密流 | 实现简单，但随机恢复、并行上传和局部损坏隔离较差 |
| tar + gzip/xz | 互操作性好，但随机访问、增量复用和远程更新不理想 |
| ZIP/7z | 适合用户归档，不适合作为长期版本化对象仓库 |
| LZ4 | 解压极快，但通常压缩率低于 Zstandard；可作为未来可选项 |

## 风险与验证

- 对 100,000 个小文件和多 GiB 大文件测量分块及 pack 大小、内存、吞吐量、请求数和随机恢复读取放大。
- 故障注入覆盖写包、写索引、加密和提交各阶段，证明旧快照不受影响。
- 对错误口令、篡改、截断、重复 nonce 检测和密钥丢失执行恢复测试。
- 对不可压缩媒体、文本、数据库和稀疏文件比较压缩策略。
- 使用独立实现或固定测试向量验证格式，避免实现只能由自身读取。
- 检查未解锁仓库，证明路径、文件名、快照清单、对象 ID 和索引不以明文泄露。
