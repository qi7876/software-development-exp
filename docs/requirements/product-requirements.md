## 1. 背景与问题

个人用户的重要文件通常散落在多个目录中，手工复制容易遗漏、重复占用空间，也无法稳定回答“某天的版本是否仍可恢复”。本产品提供可计划执行、可校验、可浏览历史且可恢复的桌面备份能力。

## 2. 目标用户

主要角色是使用个人电脑、希望保护文档和照片，但不愿维护复杂服务器的普通用户。高级用户可以通过 CLI 创建任务、触发备份和查询状态。

## 3. 产品目标与成功指标

### 3.1 目标

- 十分钟内完成首个备份任务的创建并开始运行。
- 后台按计划可靠执行，不依赖 GUI 常驻。
- 用户可以在损坏或误删源文件后，从指定快照恢复数据。
- 对备份结果执行可追溯的完整性校验。

### 3.2 MVP 验收指标

- 受支持平台上，核心端到端备份/恢复测试通过率为 100%。
- 备份成功后随机抽取文件校验，内容哈希一致率为 100%。
- 进程中断后，已提交快照保持可读取；未完成运行可明确识别且不会展示为成功。
- 对 100,000 个小文件或 100 GiB 数据集完成测试，不因文件数量或数据量耗尽内存。
- 计划任务漏触发、目标盘不可用、权限不足等失败均记录原因并通知用户。

指标中的耗时和吞吐量目标将在架构原型基准测试后确定。

## 4. 范围

### 4.1 MVP 范围内

- 本地文件和目录备份。
- 本地目录及操作系统已挂载存储作为目标。
- 多个独立备份任务。
- 手动、每日和每周计划。
- 基于内容或文件元数据判定变化的增量快照。
- 可配置排除规则（路径模式、隐藏文件、文件大小）。
- 可按路径 glob/正则、所有者、用户组、时间、扩展名及文件系统对象类型筛选，并在运行前预览结果。
- 对备份内容进行版本化打包、压缩和可选的认证加密/解密。
- 快照列表、文件浏览、原路径或自定义路径恢复。
- 内容完整性校验。
- 运行历史、结构化日志、进度与桌面通知。
- 保留最近 N 个快照；安全清理不再引用的数据。
- GUI 与 CLI。
- 核心闭环完成后，按适配器方式接入 WebDAV 与 S3 兼容对象存储（Should）。

### 4.2 MVP 范围外

- 跨设备去重和硬件密钥支持。
- 实时双向同步、文件分享、团队权限管理。
- 移动端和 Web 管理端。
- 裸机恢复及操作系统镜像。

这些能力可以进入后续路线图，但不得隐式成为 MVP 依赖。

## 5. 功能需求

| 编号 | 需求 | 优先级 | 验收摘要 |
| --- | --- | --- | --- |
| FR-01 | 用户可创建、编辑、启停和删除备份任务 | Must | 配置经校验并持久化；删除需确认且不默认删除快照 |
| FR-02 | 任务包含一个或多个源及一个目标 | Must | 拒绝源与目标的危险嵌套和不可写目标 |
| FR-03 | 用户可设置手动、每日或每周计划 | Must | 守护进程在 GUI 关闭时仍能触发任务 |
| FR-04 | 系统生成具有唯一 ID、时间和状态的快照 | Must | 只有原子提交完成的快照显示为成功 |
| FR-05 | 系统仅存储新增或变化的文件内容 | Must | 未变化文件不会重复写入内容数据 |
| FR-06 | 用户可查看实时进度并取消运行 | Must | 展示文件数、字节数、当前阶段；取消后状态明确 |
| FR-07 | 系统可校验已存储内容 | Must | 校验结果关联至快照并列出损坏或缺失对象 |
| FR-08 | 用户可浏览快照并恢复所选文件或目录 | Must | 恢复前处理冲突；恢复后校验内容 |
| FR-09 | 系统保留运行历史和诊断日志 | Must | 每次运行记录起止时间、结果、统计和错误摘要 |
| FR-10 | 用户可设置保留最近 N 个快照 | Should | 清理操作不得删除仍被保留快照引用的数据 |
| FR-11 | 系统在成功、失败和需要操作时通知用户 | Should | 可在设置中关闭非错误通知 |
| FR-12 | CLI 可完成核心任务管理与运行操作 | Should | 适合脚本调用，并提供稳定的退出码和 JSON 输出 |
| FR-13 | 系统可通过目标适配器使用 WebDAV 或 S3 兼容存储 | Should | 网络中断可安全重试；远端未完整写入的数据不会成为已提交快照 |
| FR-14 | 用户可选择不加密或使用口令保护的文本密钥文件 | Must | 密钥文件采用版本化 JSON 并认证加密主密钥；错误口令、错误密钥文件和篡改均明确失败；恢复过程不产生未验证明文 |
| FR-15 | 用户可选择自动/关闭/速度预设压缩及自动/本地/远程打包预设 | Must | 每块独立压缩加密后聚合；单块可随机恢复；读取端按元数据自动解码 |
| FR-16 | 用户可组合文件筛选规则并预览匹配结果 | Must | 支持路径、所有者/组、时间、扩展名和对象类型；预览与实际扫描使用相同引擎 |

详细流程和异常分支见[用例模型](use-cases.md)。

## 6. 非功能需求

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-01 | 数据安全 | 写入临时区域并原子提交；失败或断电不破坏已提交快照 |
| NFR-02 | 正确性 | 内容对象使用加密哈希标识；恢复及校验不能只依赖时间戳 |
| NFR-03 | 安全 | 默认最小权限；日志不记录文件内容、凭据和不必要的个人信息 |
| NFR-04 | 性能 | 扫描和复制采用有界并发与流式 I/O，内存占用不随总数据量线性增长 |
| NFR-05 | 可用性 | 危险操作二次确认；错误信息说明原因和可执行的下一步 |
| NFR-06 | 可访问性 | GUI 支持键盘操作、明确焦点、文本缩放和非纯颜色状态表达 |
| NFR-07 | 可维护性 | 核心逻辑与 UI 解耦；公共协议版本化；关键模块具备自动化测试 |
| NFR-08 | 可观测性 | 使用结构化日志和关联运行 ID；用户可导出脱敏诊断包 |
| NFR-09 | 兼容性 | 第一阶段明确一个主开发平台；其余平台通过 CI 和发布验收逐步纳入 |
| NFR-10 | 网络容错 | 远程操作具有超时、有界重试和可恢复上传机制；失败不得损坏已提交快照 |
| NFR-11 | 密钥安全 | 每个仓库使用随机主密钥；口令通过带独立盐的内存困难 KDF 派生；文本密钥文件不得包含口令或明文主密钥；密钥不得写入日志或诊断包 |
| NFR-12 | 格式兼容 | 清单、包、压缩和加密格式均记录算法及版本；未知必需算法必须拒绝读取而不是猜测 |
| NFR-13 | 筛选性能 | 规则在任务保存时编译并限制复杂度；扫描每个路径只做有界工作，正则输入不得造成灾难性回溯 |

## 7. 数据与业务规则

- 任务：名称、源列表、目标、排除规则、计划、保留策略和启用状态。
- 运行：任务的一次执行，状态为 queued、scanning、copying、verifying、succeeded、failed 或 cancelled。
- 快照：一次成功运行提交的只读文件树及其内容引用。
- 内容对象：由哈希标识的不可变文件内容；可被多个快照引用。
- 删除任务与删除备份数据是两个独立动作。
- 恢复默认不覆盖现有文件；用户可选择跳过、重命名或覆盖。
- 源文件在读取期间发生变化时，本次跳过并报告，或重新读取一次；不得静默保存不一致内容。
- 筛选规则按配置顺序执行，最后一个匹配规则决定包含或排除；默认包含普通文件、目录和符号链接。
- Unix socket、设备和 FIFO 默认排除；硬链接在支持时保存关系，否则明确降级为普通文件。
- 用户名和组名仅用于展示，规则持久化数值 UID/GID，避免重命名造成含义漂移。
- 相对时间条件以每次运行开始时间为基准；快照记录实际截止时间以便审计。
- 数据管线固定为内容定义分块、块级压缩、块级认证加密，再把密文块聚合进不可变 pack。
- 启用加密时，文件名、目录结构、文件元数据、快照清单和 pack 索引均加密；未解锁状态只公开格式和解锁必需信息。
- 解密和解压算法由块头自动选择，不要求用户在恢复时猜测；错误口令、认证失败或截断数据均不得输出最终恢复文件。
- 压缩预设为自动、关闭、快速、平衡和高压缩；打包预设为自动、本地优化和远程存储优化。

## 9. 已确认决策

- 首发平台为 macOS；最低系统版本将在打包原型后确定。
- 加密、解密、打包和压缩管线已确定；分块尺寸、pack 大小和 Argon2id 参数经技术探针确认。
- WebDAV 和 S3 是核心本地备份闭环之后的候选目标，优先级为 Should。
- 项目按单人敏捷方式推进，不承诺固定日历排期。

## 10. 发布验收

- Must 功能均满足用例验收标准。
- 单元、集成、端到端和中断恢复测试通过。
- 在目标平台完成安装、升级、卸载和后台自启动测试。
- 使用独立测试数据完成一次“备份—破坏源文件—恢复—哈希核对”演练。
- 已知限制、数据格式兼容策略和恢复说明随版本发布。
