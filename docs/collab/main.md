# Data Backup 项目协作状态

## 项目简介

Data Backup 是面向个人桌面用户、以 macOS 为首发平台的数据备份软件。当前已经完成需求与逻辑架构，并建立 Rust 多 crate 代码框架，下一步进入架构探针和最小业务闭环。

## 当前基线

- 产品需求和 20 个用例已经结构化，并可生成 Markdown、UML 和课程报告内容。
- 当前的 C1、C2、关键容器 C3、部署、逻辑类图及三个关键顺序图统一由 `docs/architecture/model.yaml` 生成；长期优先维护 C1、C2，其余视图按需更新。
- 压缩、认证加密、打包、文本密钥文件、本地/WebDAV/S3 仓库均已形成逻辑设计约束。
- Rust workspace 已包含核心、协议、后台进程和 CLI，能够统一编译、测试并执行框架自检。
- 下一步是为高风险决策建立可执行探针，并实现最小业务闭环。

## 事实来源

需求以 `docs/requirements/use-cases.yaml` 为准，架构以 `docs/architecture/model.yaml` 为准，技术决策以 `docs/decisions/` 为准。`docs/report.docx` 是课程报告的直接排版基准，生成器只能修改需求分析和系统设计目标区域，不得全局重设字体或封面格式。

## 工作方式

从最新 `main` 创建短期分支，通过 PR 审查并以 squash merge 合入。进度只在确有协作需要时记录，避免为每个分支维护一份文档。当前优先验证能运行的框架、自检命令和文档生成；业务闭环稳定后，再围绕备份、校验、恢复等外部行为和关键不变量逐步补充测试。修复明确行为的 bug 可以先写回归测试，探索性工作不强制 TDD。

本地 CI 命令：

```shell
uv run scripts/check.py
```

本地已配置远端地址，但当前访问返回“Repository not found”，无法核查远端 CI。当前只维护本地 CI，不配置 CD；远端可用后再核查现有工作流。

## 后续计划

1. 完成仓库格式、原子提交、故障清理和内容寻址探针。
2. 实现筛选与本地备份的最小可运行闭环。
3. 在行为稳定后补充低成本的关键行为测试。
4. 在核心稳定后依次实现恢复、保留、守护进程、CLI 和 GUI。
