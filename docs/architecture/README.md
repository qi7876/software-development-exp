# 项目架构

本目录维护配对开发的设计起点，只长期维护 [C1 系统上下文](system-context.md)和 [C2 容器设计](containers.md)。当前产品代码已清空，仅保留可编译的空入口；这些视图描述待实现的目标，并非当前已具备的功能。

架构说明以文字和表格为主，关系简单时使用纯文本图，不使用 Mermaid。图只辅助说明，职责、边界和约束应能从正文直接理解。

沿用已确认的方向：一个 `bak` 二进制、同进程服务器与备份业务、Web 控制台，以及供控制台和 curl 共用的 secret key 认证 HTTP API。根据实际行为增加 Rust 模块和依赖，不提前拆分 crate、进程或抽象层。当前无需 C3，C4 以之后编写的代码为准。

第一条业务闭环已确认：单个本地源、单个本地备份目标、手动备份、恢复到另一个目录并比较内容。仓库采用每次全量备份一个独立目录、JSON 清单和按文件 Zstd 压缩的方案，保证普通文件内容和目录结构，包括空目录。接下来讨论最小 HTTP API 与配置边界；运行记录持久化、校验算法和具体存储操作在相应实现步骤中验证和决定。

开发状态和协作方式见根目录 [README](../../README.md)。[课程报告](../report/README.md)保留上一阶段快照，提供需求参考，不作为当前实现状态或必须照搬的框架。
