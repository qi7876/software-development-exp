# 项目架构

本目录维护配对开发的设计起点，只长期维护 [C1 系统上下文](system-context.md)和 [C2 容器设计](containers.md)。当前产品代码已清空，仅保留可编译的空入口；这些视图描述待实现的目标，并非当前已具备的功能。

沿用已确认的方向：一个 `bak` 二进制、同进程服务器与备份业务、内置 Web 控制台，以及供控制台和 curl 共用的 secret key 认证 HTTP API。根据实际行为增加 Rust 模块和依赖，不提前拆分 crate、进程或抽象层。当前无需 C3，C4 以之后编写的代码为准。

本轮先讨论 C1 中的用户、系统边界与第一版范围，再讨论 C2 中的运行单元、配置、通信和数据归属。建议以本地手动备份和恢复作为第一条业务闭环，范围待共同确认。仓库格式、持久化方式及具体算法保持开放，在相应实现步骤中验证和决定。

开发状态和协作方式见根目录 [README](../../README.md)。[课程报告](../report/README.md)保留上一阶段快照，提供需求参考，不作为当前实现状态或必须照搬的框架。
