# Project LZ77 v1

This is a project implementation of LZ77 matching and a custom byte-oriented format, not a wrapper around a compression library. It does not implement Huffman coding, DEFLATE, ZIP, LZ4, or their interoperability contracts. Zstd remains the default general-purpose codec.

## Parameters and matching

`window_kib` is an integer from 4 to 1024 (default 64). `search_depth` is the maximum number of candidate positions inspected at each input position, from 1 to 256 (default 32). Larger windows allow references farther into history and allocate more memory; deeper searches can find better matches at greater CPU cost. They are algorithm-specific settings, not equivalents of Zstd compression levels.

The encoder holds a ring of `window_kib * 1024` history bytes, a predecessor position per history slot, 65536 hash heads, at most 258 lookahead bytes, at most 65535 pending literal bytes, and a 128 KiB buffered writer. There is no whole-file buffer. Positions use checked u64 arithmetic. A ring predecessor is usable only while its absolute position is inside the current window; nondecreasing or expired links terminate the chain.

For four lookahead bytes, form a little-endian u32, multiply by 2654435761 with wrapping u32 arithmetic, and use its upper 16 bits as the hash bucket. Search candidates newest first, inspecting at most `search_depth` links. Choose the longest match from 8 through 258 bytes; equal lengths keep the newest candidate (shortest distance). Stop immediately on a match covering all available lookahead. Hash collisions are verified byte-for-byte. Every consumed position with four available bytes enters the hash chain, including positions consumed by references. Otherwise emit a literal.

Match copying supports overlap: a reference with distance 1 can expand a repeated byte. The decoder copies one byte at a time through its ring, so newly copied bytes become available to later bytes of the same reference.

Ordinary write/read chunk boundaries do not reset the dictionary or change encoded bytes. `flush` drains available lookahead and pending literals and flushes the wrapped writer, without ending the stream; this explicit flush can affect later match choices. `finish` drains input, writes the end marker and flushes output. Failed encoders/decoders remain failed.

## Binary framing

All multibyte integers are unsigned little-endian. The header is 8 bytes `b"BAKLZ77\x01"` followed by u16 `window_kib`. The decoder validates the window before allocating its history. Search depth affects encoding only and is not needed in the payload header; complete creation parameters are retained in backup metadata.

| Tag | Remaining fields | Meaning |
| --- | --- | --- |
| 0 | u16 length, then `length` bytes | Literal run, length 1–65535 |
| 1 | u32 distance, u16 length | Copy 8–258 bytes from distance 1 through the available window history |
| 255 | none | Mandatory end marker, followed by EOF |

For example, header `BAKLZ77 01 04 00`, literal bytes `00 04 00 41 42 43 44`, reference `01 04 00 00 00 08 00`, and final `FF` decode to `ABCDABCDABCD`. The empty input is a valid header followed by `FF`.

Unknown versions/tags, invalid windows, zero-length literal runs, distances outside produced history, invalid match lengths, partial fields/data, missing end markers, and trailing bytes are errors. Short reads/writes and interrupted reads are handled by normal IO contracts. The reader validates EOF after the end marker; when layered over encryption this also forces verification of the final AEAD block. Authentication, original size and SHA-256 checks remain part of the enclosing backup/restore pipeline.

## Integration and measurement

Compression is `null` or a tagged configuration, for example `{"algorithm":"lz77","window_kib":64,"search_depth":32}`. Zstd uses `{"algorithm":"zstd","level":3}`. Backup stores the complete configuration in repository format/schema v4 and task schema v3. Encrypted payload v2 binds that configuration in AAD. No previous-format migration or fallback is provided.

Tests include independent whole-output reference decoding, a hand-encoded overlapping-reference example, ring wrap and maximum-distance examples, property tests over arbitrary bytes, malformed data, short IO, and errors. The optional optimized measurement is:

```shell
cargo test --profile profiling jobs::lz77::measurements::measure_samples -- --ignored --nocapture
```

It warms up once and measures three in-memory encoding/decoding cycles on each 1 MiB text, repeated-byte and deterministic-random sample. Fixture creation and equality comparisons are untimed. These are codec observations without filesystems, HTTP, encryption or durability costs, not application throughput guarantees. Results and environment are recorded in `docs/report/lz77-measurements.json`; no acceptance threshold or superiority over Zstd is claimed.
