# Project LZ77 v1

The project LZ77 codec uses a byte-oriented stream of literals and back-references.

## Parameters and matching

`window_kib` is an integer from 4 to 1024 (default 64). `search_depth` is the maximum number of candidate positions inspected at each input position, from 1 to 256 (default 32). Larger windows allow references farther into history and allocate more memory; deeper searches can find better matches at greater CPU cost.

The encoder holds a ring of `window_kib * 1024` history bytes, a predecessor position per history slot, 65536 hash heads, at most 258 lookahead bytes, at most 65535 pending literal bytes, and a 128 KiB buffered writer. Positions use checked u64 arithmetic. The search follows decreasing predecessor positions inside the current window.

For four lookahead bytes, form a little-endian u32, multiply by 2654435761 with wrapping u32 arithmetic, and use its upper 16 bits as the hash bucket. Search candidates newest first, inspecting at most `search_depth` links. Choose the longest match from 8 through 258 bytes; equal lengths keep the newest candidate (shortest distance). Stop immediately on a match covering all available lookahead. Hash collisions are verified byte-for-byte. Every consumed position with four available bytes enters the hash chain, including positions consumed by references. Otherwise emit a literal.

Match copying supports overlap: a reference with distance 1 can expand a repeated byte. The decoder copies one byte at a time through its ring, so newly copied bytes become available to later bytes of the same reference.

The dictionary and encoded bytes are independent of ordinary IO chunk boundaries. `flush` drains available lookahead and pending literals, then flushes the wrapped writer. Explicit flushes can affect later match choices. `finish` drains input, writes the end marker and flushes output. Failed encoders/decoders remain failed.

## Binary framing

All multibyte integers are unsigned little-endian. The header is 8 bytes `b"BAKLZ77\x01"` followed by u16 `window_kib`. The decoder validates the window before allocating its history. Search depth affects encoding. The manifest stores both parameters.

| Tag | Remaining fields | Meaning |
| --- | --- | --- |
| 0 | u16 length, then `length` bytes | Literal run, length 1–65535 |
| 1 | u32 distance, u16 length | Copy 8–258 bytes from distance 1 through the available window history |
| 255 | none | Mandatory end marker, followed by EOF |

For example, header `BAKLZ77 01 04 00`, literal bytes `00 04 00 41 42 43 44`, reference `01 04 00 00 00 08 00`, and final `FF` decode to `ABCDABCDABCD`. The empty input is a valid header followed by `FF`.

Unknown versions/tags, invalid windows, zero-length literal runs, distances outside produced history, invalid match lengths, partial fields/data, missing end markers, and trailing bytes are errors. Short reads/writes and interrupted reads are handled by normal IO contracts. The reader validates EOF after the end marker; when layered over encryption this also forces verification of the final AEAD block. Authentication, original size and SHA-256 checks remain part of the enclosing backup/restore pipeline.

## Integration and measurement

Select LZ77 with `{"algorithm":"lz77","window_kib":64,"search_depth":32}`. The manifest and job request store both parameters. Encrypted payloads bind the configuration in associated data.

Run the optimized codec benchmark.

```shell
cargo test --profile profiling jobs::content::lz77::measurements::measure_samples -- --ignored --nocapture
```

It warms up once and measures three in-memory encoding/decoding cycles on each 1 MiB text, repeated-byte and deterministic-random sample. Timing covers in-memory encoding and decoding. Results and the measurement environment are recorded in [lz77-measurements.json](../report/evidence/lz77-measurements.json).
